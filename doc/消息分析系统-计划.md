# 消息分析系统 — 实施计划

> 决策确认：2026-08-26（grill-me 答复 + 消息来源文档）

## 一、目标与边界

**定位**：面向未来的辅助信息整理，帮助用户归集、筛选、标注多源快讯与财经日历事件。不荐股、不预测涨跌、不给买卖时机（与 `CONTEXT.md` 一致）。

**不做（v1）**：

- 与自选股 / 涨停池自动联动
- 资讯雷达接入或同步
- AkShare 财联社等备用源（文档已记录，后续阶段）
- effect_status 自动更新（默认 `not_erupted`，人工改）
- 分析结果自动注入复盘 prompt（与经验记忆相同：**可勾选**注入，v2）

**要做（MVP）**：

- 多源统一模型：原始消息 + 分析后消息
- 手动粘贴 / 结构化 JSON 录入 + 拆分预览与 UI 调整
- 选股宝 `pc/msgs` HTTP 轮询，HeadMark/TailMark 增量
- 财经大事日历（结构化录入，带指定生效时间）
- SQLite 落盘 `~/.duanxian-agents/messages/`
- 列表：筛选、排序、全文搜索
- AI 分析：手动触发，批量走队列

## 二、数据模型

### 2.1 原始消息 `raw_message`

| 字段 | 说明 |
|------|------|
| `id` | `msg_{uuid8}` 或来源稳定 ID（选股宝用 `Id`） |
| `source_id` | 来源注册 ID |
| `content` | 完整原文（TEXT） |
| `title` | 标题（有则填） |
| `keywords` | 关键词 JSON 数组 |
| `url` | 链接 |
| `marks` | 标记 JSON 数组，如 `["highlight"]`（财联社标红等） |
| `content_hash` | 去重 |
| `batch_id` | 同批粘贴 |
| `external_ref` | 外部 ID / URL |
| `produced_at` | 消息产生时间 |
| `ingested_at` | 入库时间 |
| `meta` | 扩展 JSON（拆分规则、原始格式等） |

### 2.2 分析后消息 `analyzed_message`

在原始字段基础上增加：

| 字段 | 说明 |
|------|------|
| `summary` | 摘要（≤120 字） |
| `detail` | 详情（Markdown） |
| `title` | 标题 |
| `keywords` | 关键词 JSON 数组 |
| `url` | 链接 |
| `marks` | 标记 JSON 数组（如 `highlight` 表示财联社标红） |
| `effective_mode` | `immediate` / `scheduled` |
| `effective_at` | 指定生效时间；立即时为空 |
| `targets` | 影响标的 `[{kind, code, name}]`，UI 显示 name，属性带 code |
| `impact_level` | `critical` / `high` / `medium` / `low` / `noise` |
| `freshness` | `new` / `follow_up` / `duplicate` / `rumor`（**AI 判断**，提示词约束，不查库） |
| `effect_status` | `not_erupted` / `early_hype` / `ongoing_hype` / `already_hyped` / `faded` / `invalid` |
| `analyzed_at` / `analyzed_by` | `ai` / `human` / `rule` |
| `version` / `status` | `draft` / `confirmed` / `archived` |

**回测口径**：生效「立即」按 `produced_at` 计。

### 2.3 来源注册 `message_source`

| source_id | 类型 | 说明 |
|-----------|------|------|
| `paste` | manual | 大段文字粘贴 |
| `structured` | manual | JSON 结构化 |
| `xgb_msgs` | poll | 选股宝 `pc/msgs`，主源 |
| `calendar` | manual+poll | 财经大事日历，带 `effective_at` |

轮询状态表 `poll_state`：`source_id`, `head_mark`, `tail_mark`, `last_poll_at`, `last_error`。

## 三、存储

**路径**：`~/.duanxian-agents/messages/messages.db`（WAL，与复盘 JSON 同级备份策略）

**表**：`message_source`, `raw_message`, `analyzed_message`, `raw_analyzed_link`, `impact_target`, `poll_state`, `analyze_job`

**搜索**：`title`, `summary`, `detail`, `keywords`, `content` 的 LIKE + 索引；数据量大后再上 FTS5。

**去重**：

- 有稳定 ID（选股宝）：`UNIQUE(source_id, external_ref)`
- 无 ID：`content_hash` UNIQUE

---

## 四、解析器

```
IngestPayload → Adapter.can_handle → Adapter.parse → Splitter → RawMessageDraft[]
                                                      ↓
                                              UI 预览 / 合并 / 再拆分
                                                      ↓
                                              store.insert_raw()
```

| 适配器 | 输入 | 拆分 |
|--------|------|------|
| `PasteAdapter` | `format=plain` | 空行 / `---` / 序号 / 可选 LLM |
| `StructuredAdapter` | `format=structured` | 数组每项一条；单对象一条 |
| `XgbAdapter` | API JSON | 每条 NewMsgs 一条 raw |
| `CalendarAdapter` | 日历 JSON | 每条事件一条，`effective_mode=scheduled` |

**UI 调整**：`POST /api/messages/ingest/preview` 只返回草稿；确认后 `POST /api/messages/ingest/commit`；支持 `merge` / `resplit` 操作。

## 五、选股宝轮询（增量）

参考 `doc/消息来源.md` §2.1：

```
GET https://api.xuangubao.cn/api/pc/msgs?subjids=9,10,723,35,469,821&limit=30
```

- 响应 `NewMsgs` / `UpdatedMsgs` / `DeletedMsgs` + `HeadMark` / `TailMark`
- 入库映射：`Id→external_ref`, `Title→title`, `Summary+Content→content`, `AllStocks→targets`, `BkjInfoArr→targets`, `CreatedAtInSec→produced_at`, `Image→url`（配图）
- `IsWithdrawn=true` → 标记 `archived` 或软删
- 后台 daemon 线程，默认 **30s** 间隔（可 `MESSAGE_POLL_INTERVAL` 环境变量）
- `POST /api/messages/poll/xgb` 手动触发

## 六、API 一览

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/messages/sources` | 来源列表与轮询状态 |
| POST | `/api/messages/ingest/preview` | 解析预览（不写入） |
| POST | `/api/messages/ingest/commit` | 确认入库 |
| POST | `/api/messages/ingest/adjust` | 合并/再拆分后提交 |
| GET | `/api/messages/raw` | 原始列表（筛选/排序/搜索） |
| GET | `/api/messages/analyzed` | 分析列表 |
| GET | `/api/messages/analyzed/{id}` | 详情 |
| PATCH | `/api/messages/analyzed/{id}` | 人工修正 |
| POST | `/api/messages/analyze` | 触发分析（ids[]，入队） |
| GET | `/api/messages/analyze/queue` | 队列状态 |
| POST | `/api/messages/poll/xgb` | 手动轮询选股宝 |

**列表查询参数**：`source`, `q`, `from`, `to`, `impact_level`, `effect_status`, `status`, `sort`（`produced_at`/`ingested_at`/`impact_level`）, `order`, `limit`, `offset`

## 七、前端页面 `MessageAnalysis`

路由 `/messages`，侧边栏「消息分析」。

**布局**：

1. **工具栏**：来源筛选、时间范围、级别/生效状态、搜索框、排序
2. **录入区**（可折叠）：粘贴 / JSON / 日历事件表单；拆分预览表格，支持删行、合并选中
3. **列表**：标题、来源、产生时间、级别、生效状态、标的标签（显示名，hover 见 code）
4. **详情抽屉**：原文 | 分析对照；人工编辑；「AI 分析」按钮
5. **批量**：多选 → 入队分析

**经验记忆式勾选**（v2）：问 AI 时可勾选「附带已选消息」—— MVP 仅预留 localStorage key。

---

## 八、AI 分析

- 手动触发，不自动跑
- 批量：`analyze_job` 表 FIFO 队列，后台线程逐条处理
- 提示词要点：
  - 输出严格 JSON 符合 schema
  - `freshness` 由模型根据正文判断，**禁止**引用系统已有消息
  - 不输出买卖建议、目标价
- 默认 `status=draft`，用户确认 → `confirmed`
