# 仓位预算 —— 定档规则

> 情绪管「最多几成仓」，不管买卖点。全流程纯硬规则，不经 LLM，不进 AI prompt。
>
> 代码：`duanxian/trade_budget.py`（定档与 Cap）、`duanxian/risk_stance.py`（读数组装、guard、单笔预览）、`duanxian/trade_store.py`（落盘与账户）、`duanxian/trade_phase_config.py`（档位表覆盖）。

## 一、整体流程

```
gather_readings(date)        组装当日读数（纯计算）
        ↓
collect_gap_reasons()        缺关键读数 → 整日预算不可用，直接返回
        ↓
classify_rule_phase()        硬规则定档 → rule_phase
        ↓
width_divergence() → demote()   宽度背离命中 → 沿防守方向降一档
        ↓
override_phase               人手覆盖（最高优先级）
        ↓
caps_for() / actions_for()   查档位表 → cap_total、cap_single、允许/禁止
        ↓
guard() / size_preview()     现仓对照、减仓顺序、当日亏损闸、单笔金额
```

落盘在 `~/.duanxian-agents/trade/{date}.json`，同日重算保留已有手拨覆盖。

## 二、读数来源

`risk_stance.gather_readings` 组装，全部来自已有的复盘数据，不额外抓盘：

| 读数 | 来源 | 用途 |
|---|---|---|
| `limit_up` 涨停家数 | ShortBoard 情绪全景口径：趣财经 `qcj_zt`（归档→API）→ 开盘啦 `n_sjzt` → `day_summary` | 冰点判定 |
| `broken_rate` 炸板率 | `emotion_metrics.day_summary` | 过热、退潮判定 |
| `highest` 最高连板 | `settled_archive.emotion_half` 的梯队，回退到 day_summary | 四道闸全部依赖 |
| `highest_hist` 近 5 场最高连板 | 逐日 `day_summary` | 高度压降 / 近窗高位 |
| `money_median` 赚钱效应中位 | `settled_archive.emotion_half` | 高潮、冰点、退潮、宽度背离 |
| `promotion_1to2` 1进2 晋级率 | `settled_archive.emotion_half` | 冰点、退潮判定 |
| `deep_loss_5_rate` 深亏占比 | `market_facts.loss_effect` | 退潮判定 |
| `market_limit_down` 跌停家数 | 同情绪全景：趣财经 `qcj_dt`（归档→API）→ 开盘啦 `n_sjdt` → `loss_effect`（定稿路径常空） | 退潮判定、修复代理 |
| `up` / `down` 涨跌家数 | `breadth.market_breadth` | 宽度背离 |
| `index_pct` 上证涨跌幅 | 实时行情，仅当它属于该已收盘场次 | 宽度背离 |

前一场的 `money_median`、`promotion_1to2`、`market_limit_down` 一并取，供修复代理做同比。

可选合成情绪分 `S`（设置页「合成情绪分 S」）：

| 算法 | 说明 |
|---|---|
| `hard_rules`（默认） | 不算 S，定档走第四节硬规则树 |
| `qcj_degree` | 趣财经 `temperatureDegree` 当 S |
| `percentile_qcj_em` | 趣财经 ~220 日 + 东财补炸板/高度（优先本机 AKTools），分位等权合成；有两融缓存时并入 `margin_chg` |
| `fusionintel` | 聚变智研宏观恐贪原样当 S（须保存 API Key） |

有可用 S 时：退潮/过热叠加仍优先于 S 区间；区间为 `S < 20` 冰点、`20–55` 升温、`55–80` 高潮、`S > 80` 过热。`修复确认` 仍只手拨。

## 三、整日不可用闸

`collect_gap_reasons` 任一命中，当日预算 `available: false`，不给假 Cap，`block_new_long_reasons` 写入原因：

- 涨停池摘要不可用
- 赚钱效应不可用
- 晋级率不可用
- 摘要可用但炸板率缺失

**跌停家数、涨跌家数、指数涨跌幅缺失不阻断**，只是让依赖它们的分支静默跳过。

## 四、六档硬规则

`classify_rule_phase` 按顺序四道闸，全部落空才落到兜底档。**「修复确认」永不自动产出，只能手拨进入。**

| 顺序 | 档位 | 命中条件 |
|---|---|---|
| 1 | **退潮杀伤** | 高度压降 **且** 数据转差 |
| 2 | **过热防守** | 高度处近窗高位 **且** 炸板率 ≥ 40% |
| 3 | **高潮拥挤** | 最高连板 ≥ 5 **且** 赚钱效应中位 ≥ 0 |
| 4 | **冰点观察** | 最高连板 ≤ 3 **且**（赚钱效应 < 0 或 1进2 < 15% 或 涨停 < 30 家） |
| 5 | **升温扩张** | 以上全部未命中（兜底分支） |

其中：

- **高度压降**：近 5 场最高连板的峰值 ≥ 当前高度 + 1，且峰值 ≥ 4。
- **数据转差**（任一即可）：炸板率 ≥ 40%、1进2 < 20%、赚钱效应中位 < 0、深亏占比 ≥ 25%、跌停 ≥ 20 家。
- **近窗高位**：当前高度 ≥ 近 5 场峰值 且 ≥ 4；无历史窗时退化为 ≥ 5。

## 五、宽度背离降档

`width_divergence` 三条同时成立才算命中：指数**上涨**、上涨家数占比 < 45%、赚钱效应中位 < 0。四个读数缺任一则跳过。

命中后沿防守方向降一档：

```
升温扩张 → 高潮拥挤 → 过热防守 → 退潮杀伤（地板）
冰点观察 → 退潮杀伤
修复确认 → 冰点观察
```

「修复确认」只可手拨进入，因此不作为降档落点。

## 六、手拨覆盖与修复代理

`set_override` 写入 `override_phase`，优先级高于规则档与降档结果；非六档之一直接判整日不可用。清除覆盖传空。

`repair_proxy_met` 是「修复确认」的代理检查，**只提示，不自动升档**，三项全过才算满足：

- 赚钱效应中位转正或较昨回升
- 1进2 较昨回升
- 跌停家数较昨减少（两日都取不到时判不满足）

只有当**前一场的 `rule_phase` 是冰点观察**时，代理结论才会写进 `classify_reasons`。

## 七、档位表与闸门

`_CAP_TOTAL` 是内置默认总仓；**单票默认 = 总仓 / 2**（本项目按实际操作需要定下的规则，不跟源文档单票区间走）。总仓、单票、提示词都只是默认值，可在设置页界面手改，覆盖落盘到 `~/.duanxian-agents/config/trade_phases.json`。

| 档位 | 总仓上限 | 单票默认 | 允许 | 禁止 | 扩张性开仓 |
|---|---|---|---|---|---|
| 冰点观察 | 20% | 10% | 分批试错、低吸确认 | 追连板、满仓梭哈 | 否 |
| 修复确认 | 40% | 20% | 主线首板/二板、核心回踩 | 乱扫跟风杂毛 | 是 |
| 升温扩张 | 60% | 30% | 顺势加仓、持有核心 | 逆势抄底杂毛 | 是 |
| 高潮拥挤 | 40% | 20% | 兑现部分、降集中度 | 新开高位接力仓 | 否 |
| 过热防守 | 20% | 10% | 只减不加、只做防守 | 任何扩张性开仓 | 否 |
| 退潮杀伤 | 0% | 0% | 空仓或极轻仓观望 | 抄底、接飞刀 | 否 |

冰点档允许分批试错，但闸门仍标为非扩张。

`block_new_long_reasons` 汇总以下来源：档位本身（过热/退潮禁止扩张、高潮禁止新开高位接力）、宽度背离已降档、未录入总权益、总仓已达当前档 Cap_total、触及当日亏损限额。

## 八、单笔金额

`size_amount`：

```
单笔 = min(权益 × 单票上限, 权益 × 单笔风险 ÷ 止损幅度, 剩余总仓) × 板位折扣
```

板位折扣：首板 1.0×，二板 0.7×，三板及以上 0.4×，未填按首板；「高潮拥挤」档再 ×0.5。

默认常量（可在账户里改）：单笔风险 0.5%、当日亏损限额 2%、MaxDD 软 8% / 硬 12%。MaxDD v1 只落权益快照，不自动执行。

# 来源与偏离

## 直接来源

本机文档 `G:\Projects\Stock\量化交易\文档\仓位风控量化.md`（整理日期 2026-08-18）。2026-08-19 的 grilling 会话以「结合本项目已有数据与该文档，落地仓位风控」开场；`doc/todo/仓位风控-v1延期.md` 里「对应 grilling 共享理解（2026-08-19）」即此次。

从源文档**忠实抄入**的部分：

- 六个档位名与每档允许 / 禁止动作
- 总仓取文档区间**低端**（20 / 40 / 60 / 40 / 20 / 0）
- 单笔公式 `min(单票上限, 风险倒推, 剩余总仓)` 与板位折扣（1.0 / 0.7 / 0.4，高潮再 ×0.5）
- 宽度背离「指数涨 + 上涨家数差 + 赚钱效应转负 → 至少降一档」
- 账户常量：`Risk_per_trade`、`DailyLossLimit`、`MaxDD_soft` / `MaxDD_hard`
- 「情绪管总仓上限，不管买卖点」的产品边界

## 相对源文档的差异

### 已定案（本项目不改）

**单票默认 = 总仓 / 2。** 源文档给的是更紧的单票区间（如升温扩张 10%–15%）；本项目按实际操作需要改成「总仓一半」作为内置默认，**不打算改回文档区间**。总仓 / 单票 / 提示词都只是默认值，设置页可手改并落盘覆盖——需要更紧的单票上限时在界面改即可，不必动代码。

对照仅作存档，不当作待修项：

| 档位 | 源文档单票 | 本项目默认单票 |
|---|---|---|
| 冰点观察 | 5%–8% | 10%（总仓一半） |
| 修复确认 | 8%–12% | 20% |
| 升温扩张 | 10%–15% | 30% |
| 高潮拥挤 | 8%–10% | 20% |
| 过热防守 | 5% | 10% |

### 仍可能导致已知问题的偏离

#### 1. 定档主输入 `S` 被拿掉了

源文档第 3 节以合成情绪分 `S`（0–100）为主输入：「升温扩张 = `S` 在 20–55，宽度尚可」——这是**正向条件**。代码没有 `S`（延期项第一条即「历史分位数合成 S，替换无 S、纯涨停生态硬规则」），于是改成判定树的 `else` 兜底。

**后果**：兜底档 = 最激进档（见已知问题 1）。这不是源文档的设计，是丢掉 `S` 之后的代偿。

#### 2. 宽度背离照抄了文档的洞

源文档原文只写「指数涨但上涨家数差…」，没写指数跌 + 宽度极差怎么办。代码 `index_pct > 0` 是忠实实现，因此指数下跌的弱宽度日不降档（见已知问题 3）。

#### 3. 「修复确认」从升档规则降级成代理提示

源文档：「冰点后出现核心人气股低开强反包 / 地天 → 才允许升到修复确认」。代码没有该硬字段（也在延期清单），改成三项代理检查 + 只提示不升档；再叠加次日只读 `rule_phase` 不读 `phase`，形成「退潮之后无过渡直接 60%」（见已知问题 4）。

## 公开语境（非单一权威出处）

六档框架与涨停生态指标（最高连板、涨停家数、炸板率、晋级率、赚钱效应）是 A 股短线 / 游资圈通识，淘股吧、约投顾、东财财富号等复盘教程里到处可见，阈值也常与本系统接近（涨停 < 30 ≈ 冰点、炸板 > 40% ≈ 退潮、最高板 ≥ 5 ≈ 高潮）。源文档第 3 节判定列自己标了「（示例）」——没有单一论文或白皮书可追到「本系统六档的发明人」。

较接近的机构研究：

- **国泰海通**《大类资产与中观配置研究（五）——从涨停板、"打板策略"到赚钱效应引发的情绪择时指标》（2025-05-14，郑雅斌 / 余浩淼 / 曹君豪）。用涨停占比、跌停占比、净涨停占比、打板收益、跌停次日收益做择时；输出是连续仓位信号，不是分档 Cap。研报附带结论：2016 年以来打板策略每次交易平均收益约 −0.93%。开源复现见 [Sentiment-timing-report-reappear](https://github.com/therealXiaomanChu/Sentiment-timing-report-reappear)。

学术文献对「连板高度高 → 可加仓」方向相反：

- [NBER w24014《Daily Price Limits and Destructive Market Behavior》](https://doi.org/10.3386/w24014)：大户涨停日买、次日卖，涨停日净买入预示更强长期反转。
- [Finance Research Letters (2024)《Price limits hitting effect…》](https://ideas.repec.org/a/eee/finlet/v60y2024ics1544612323011753.html)：频繁涨停个股未来收益显著更低，牛市更明显。

这不否定把情绪当**仓位天花板**（源文档第 1、9 节的核心原则），但否定把它当进攻信号。

单笔公式本身不是 A 股特有：经典 fixed fractional（`Size = Equity × Risk% ÷ Stop`），Van Tharp 一脉；默认单笔风险 0.5% 在行业惯例 0.5%–2% 内。

类似开源多停在复盘指标层（如 [stock-review-tool](https://github.com/qtfy2021/stock-review-tool-)、[replay](https://github.com/NNNightglow/replay)），把情绪映射成仓位 Cap 这一层是源文档独有的设计。

# 已知问题

以下为 2026-08-24 场次复核时发现的问题，按影响排序。多数是上文「相对源文档的偏离」的直接后果。案例读数：最高连板 4（近窗 [4,4,3,4,3]）、炸板率 25.8%、赚钱效应中位 −1.63、1进2 14.0%、深亏占比 24.1%、涨跌家数 1421/3736、上证 −0.59%、跌停家数取不到。结果定在「升温扩张」，总仓 60%。

## 1. 兜底档就是最激进档（偏离 1 的后果）

「升温扩张」是四道防守闸全部落空后的 `else` 分支，却对应全表最高的 60% 总仓。任何**读数怪异但恰好都没踩阈值**的日子，都会拿到最大敞口，而不是最小敞口。源文档里升温扩张需要 `S` 落在 20–55 的正向条件；无 `S` 后变成兜底，性质变了。

2026-08-24 就是这种情况：指数跌 0.59%、3736 家下跌、赚钱效应中位为负、1进2 只有 14%，`classify_reasons` 里唯一一句是「未命中防守/冰点/高潮条件 → 升温扩张」。

可能修法：补回 `S`，或至少把「升温扩张」改成需要正向条件（赚钱效应 ≥ 0、晋级率达标、涨停家数达标）才能进入，兜底落到更保守的档。

## 2. 高度是四道闸的单点否决

冰点要求高度 ≤ 3，退潮要求高度压降，过热要求高度近窗高位，高潮要求高度 ≥ 5。高度一旦卡在「不高不低」，赚钱效应和晋级率再差也无法把档位压下来。源文档强调「定档时优先看共振，不单看 S」；无 `S` 后高度成了几乎唯一的结构轴，共振变成了串联否决。

2026-08-24 的退潮判定里，「数据转差」那一半其实已成立（1进2 14% < 20% 阈值），唯一挡住它的是高度压降不成立——当前高度 4，近窗峰值也是 4，差 1 才够。同时高度 4 > 3，冰点分支的赚钱效应条件根本不参与计算。

可能修法：给赚钱效应 / 晋级率 / 宽度设一条不依赖高度的独立降档通道。

## 3. 宽度背离只在指数上涨时生效（偏离 2 的后果）

`width_divergence` 要求 `index_pct > 0`。规则的本意是抓「指数涨但个股跌」的假强，但实现结果是**指数下跌 + 宽度极差的日子完全不触发降档**——源文档本身也没写这条，代码是照抄了洞。

2026-08-24 上涨占比 27.6%（远低于 45% 阈值）、赚钱效应 −1.63，两条都满足，只因指数 −0.59% 而判 `hit: false`。

可能修法：拆成两条规则，指数跌 + 宽度极差单独走一条降档路径。

## 4. 手拨的档不传递给第二天（偏离 3 的后果）

`compute_day` 取前一日的 `rule_phase` 作为 `prev_rule_phase`，而不是实际生效的 `phase`。手拨结果对次日完全不可见。

2026-08-21 的规则档是「退潮杀伤」，手拨成了「冰点观察」；2026-08-24 读到的 `prev_rule_phase` 是「退潮杀伤」，所以「上一交易日为冰点观察 → 提示修复代理」那段逻辑没触发，当天 `classify_reasons` 里只有兜底一句。

叠加问题 1，档位从手拨的 20%（规则档 0%）无过渡直接跳到 60%，中间的「修复确认」因为只能手拨而被跳过。源文档里修复确认本应是冰点后的升档确认节点。

## 5. 档位表覆盖只活在进程内存里

`trade_phase_config` 的覆盖表 `_TABLE` 是进程内缓存。若界面改过总仓 / 单票但磁盘上的 `trade_phases.json` 丢失或未写入，重启后会静默回落到内置默认（单票 = 总仓 / 2），手改结果看起来「丢了」。

说明：回落到「总仓一半」本身是预期默认，不是 bug；真正的问题是**覆盖落盘与进程缓存不同步**，手改值可能在重启后消失。

可能修法：定档 / 读配置时把生效来源一并落盘或校验；覆盖表缺失时显式告警，而不是静默回落。
