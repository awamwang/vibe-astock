# 消息优先级：优化落地路径

> 日期：2026-09-12。依据 [消息优先级-AI判定方法](./消息优先级-AI判定方法.md)；本文件记录已选定落地顺序与字段语义。

## 目标

- 模型不再直接打工作档 `impact_level`，改为多维因子 → 服务端合成。
- **三档独立保存与展示**：
  | 字段 | 含义 | 谁写入 |
  |------|------|--------|
  | `initial_impact_level` | 来源先验（财联社/日历/插件等） | 入库；人工改工作档时同步 |
  | `ai_impact_level` | AI 客观合成档（不含关注升档） | 仅 AI 分析 |
  | `impact_level` | 工作档（列表排序/筛选/主徽章） | 入库关注升档；未手动时可由 AI 合成档+关注升档覆写；人工改档后冻结 |

`impact_manual=true` 后：AI 仍可更新 `ai_impact_level`，但不再改 `impact_level`。

## 本轮落地（①②）

### ① P0：多维打标 + 服务端合成 + 锚点 prompt

- 扩展 `analyze` JSON：`scope` / `magnitude` / `actionability` / `credibility` / `time_sensitivity` / `is_rumor` / `rationale`。
- System prompt 写入五档锚点与负例；禁止用「可能影响股价」抬档。
- `synthesize_ai_impact_level`：固定权重合成 → 写入 `ai_impact_level`；`rumor`/`is_rumor` 降一档；`freshness=duplicate` 封顶 medium。
- 兼容：若模型仍只返回旧字段 `impact_level` 而无因子，则将该值视为 AI 档回退。
- **重算入口**：`POST /api/messages/analyze/run` 传 `mode=impact`；详情与列表有「重算 AI 级别」按钮，只更新 AI 档相关字段。

### ② P1：关注升档在合成之后；客观与个人分离

- `ai_impact_level`：**不含**关注词/板块升档。
- 未手动时工作档 = `boost(ai_impact_level)`（命中关注）或 `ai_impact_level`。
- 入库新建仍：`initial` = 来源先验，`impact_level` = 先验+关注升档；`ai_impact_level` 为空直至 AI 跑过。

## 后续（未做）

| 优先级 | 动作 |
|--------|------|
| P1 | 人工改档对照集 + 混淆矩阵（≥50 条再调权重） |
| P2 | few-shot 锚点库 / 同批相对排序 |
| P2 | 小模型过筛 + 大模型精标 |
| 并行 | 新旧程度：主张指纹 → 库内召回 → 差分（见 [消息新旧程度-AI判定方法](./消息新旧程度-AI判定方法.md)） |
