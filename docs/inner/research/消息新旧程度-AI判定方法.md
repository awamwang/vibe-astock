# 消息新旧程度：纯 AI 判定方法

> 日期：2026-08-30。范围：单条 A 股资讯/电报的「历史上是否炒过、本次是否实质新」判定；对照本仓库已有 `freshness` / `effect_status`，不涉及买卖点或仓位建议。

## 结论摘要

- **拆两层，勿混成一次「新不新」**：文本/事件是否同一条线 → `freshness`；同类叙事是否已被市场反复炒作 → `effect_status`。
- **推荐主路径**：主张指纹抽取 → 历史召回 → LLM 差分判决；不要端到端「读全文直接判新旧」。
- **「实质变动也算新」**写进差分规则（幅度/时间表/范围/确定性升维/方向反转），仅换标题复读不算。
- **纯 AI 对「炒过」只能弱代理**（同叙事复发/冷却后再发）；要对齐盘面需叠复盘与情绪，超出纯 AI。
- **第三方**：无对口「输入一条消息 → 返回新旧+是否炒过」的接口；落地用下方组合建议，不依赖单一 SaaS。

---

## 1. 本仓库现状

| 字段 | 枚举（相关） | 语义直觉 |
|------|--------------|----------|
| `freshness` | `new` / `follow_up` / `duplicate` / `rumor` | 是否同一事件线、有无实质增量 |
| `effect_status` | 含 `ongoing_hype` / `already_hyped` 等 | 叙事是否已在炒 / 已炒过 |

定义见 `vr/message/schemas.py`。当前 AI 分析对库内历史引用受限时，续报/重复只能弱判（见 [消息优先级-AI判定方法](./消息优先级-AI判定方法.md)）。

---

## 2. 核心拆分

| 问题 | 在问什么 | 对应字段 |
|------|----------|----------|
| 文本/事件是否同一件事 | 措辞变了，事实是否同一条 | `freshness` |
| 叙事是否已被市场炒过 | 同类题材是否已有过一轮定价/情绪 | `effect_status` |

「历史上炒过」偏第二层；「实质有变动也算新」偏第一层的 **delta**。

---

## 3. 推荐主路径：主张指纹 → 召回 → 差分

不要直接拿原文做相似度。股市消息改写极多：原文相似 ≠ 同一事件，原文不相似也可能是同题材复读。

### 3.1 结构化抽取（主张卡）

每条消息由模型输出固定 schema，例如：

- `claim`：一句话主张（去情绪、去媒体腔）
- `entities`：标的 / 板块 / 政策主体
- `event_type`：政策落地、业绩、并购、制裁、传闻、解读…
- `polarity`：利好 / 利空 / 中性
- `specificity`：数字、时间点、范围（有无「首次」「扩大」「延期」）
- `certainty`：官宣 / 媒体 / 传闻
- `time_anchor`：生效日、会议日、披露日

### 3.2 检索历史同类主张

用主张卡（或 embedding）在历史库召回 Top-K；同标的 / 同题材 / 同 `event_type` 优先。

### 3.3 LLM 只做差分判决

当前主张卡 + 历史 Top-K，窄任务输出：

| 判决 | 含义 |
|------|------|
| `duplicate` | 事实与结论无实质增量 |
| `follow_up` | 同一事件线的进展 / 确认 / 辟谣 |
| `new` | 新事件，或旧事件但有实质变动 |
| `rumor` | 低确定性复读 |

**实质变动**（至少命中一项才可抬到 `new` / 有增量的 `follow_up`）：

- 量化幅度变了（补贴比例、涨价幅度、产能数字）
- 时间表变了（推迟 / 提前 / 落地）
- 覆盖范围变了（试点 → 全国、单股 → 板块）
- 确定性升维（传闻 → 官宣）
- 方向反转（利好 ↔ 利空）

仅「又一篇解读、换个标题」→ 不算新。

### 3.4 「炒过」在纯 AI 下的近似

无涨跌幅时只能弱代理，勿伪装成市场结论：

- 同 `entities + event_type` 近 N 个交易日反复出现 → 偏 `ongoing_hype`
- 同类主张间隔很长且无新 delta → 偏 `already_hyped`（旧题材复读）
- 有实质 delta：即使题材老，`freshness` 可为 `new` / `follow_up`，`effect_status` 仍可为 `ongoing_hype`

更准：主张新旧（AI）× 复盘/情绪/涨停链（规则）合判。

### 3.5 落地注意

1. **实体归一化**后再比（简称、政策别名、板块名），否则召回漏。
2. **时间衰减**写进规则：数日内同主张偏跟进；数月后同主张无 delta 偏旧炒复读。
3. **强制引用证据**：判决须指出对比的历史 id 与差在哪一点，便于 draft→confirmed 人工纠偏。

## 4. 第三方与召回：组合建议

市面上没有对口的「新旧程度判定」接口；不枚举各家产品，落地按组合使用：

```text
外库召回（Tushare 资讯 / 自建归档；可选带事件聚类的国际新闻 API）
        ↓
主张指纹 embedding 检索
        ↓
自研 LLM 差分（「新旧 + 实质变动」的唯一可靠层）
```

- **只关心本系统是否见过**：优先自有 `raw` / `analyzed` 消息库，不必上外库。
- **要补「历史上是否出现过同类主张」**：用可按时间窗拉取的历史资讯库（如 Tushare `news` / `major_news`）或终端资讯作候选召回；判决仍用自研差分。
- **「是否炒过」对齐盘面**：外库给不了，需叠本仓库复盘 / 情绪等规则信号。
- **商业新闻 API 的事件聚类 / 近重复**：最多帮「找相似报道、并成事件」；不替代差分规则，也不替代 A 股题材炒作判断。

---

## 5. 与现有字段的映射（落地时）

| 差分结果 | 建议写入 |
|----------|----------|
| 无增量复读 | `freshness=duplicate` |
| 同线进展 | `freshness=follow_up` |
| 新事件或实质 delta | `freshness=new` |
| 低确定性复读 | `freshness=rumor` |
| 近窗同叙事反复 | `effect_status=ongoing_hype`（可与上并存） |
| 长间隔无 delta 复读 | `effect_status=already_hyped` |

具体阈值（近窗天数、相似度门槛）实现时再定，本文只定方法。

---

## 6. 明确不做

- 让模型无历史上下文直接答「历史上炒过没有」。
- 用原文余弦相似度单独替代主张差分。
- 把「对我重要」与「新不新」塞进同一 prompt（相关度见优先级文档）。
