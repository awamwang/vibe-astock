# 飞书插件：持久化与表格消息工具调研

> 日期：2026-09-18。范围：本仓库（vibe-astock）若做飞书插件，四项能力——云空间存文件（不是本地磁盘）、多维表格（Bitable / Base）、电子表格（Sheets）、发消息（IM）——对应哪些**官方**成熟工具。只采用官方仓库 README / SKILL.md、官方 SDK 源码目录、官方 OpenAPI 文档与本仓库插件文档。社区技能只作一句排除，不展开。

## 结论摘要

- **插件进程内推荐官方 Python SDK**：PyPI 包名 `lark-oapi`，仓库 [larksuite/oapi-sdk-python](https://github.com/larksuite/oapi-sdk-python)（默认分支文档在 `v2_main`）。`pip install lark-oapi`，要求 Python 3.8+。`Client.builder().app_id(...).app_secret(...).build()` 后按业务域调用；源码 `lark_oapi/api/` 下有 `drive`、`bitable`、`sheets`、`im`。这与本仓库 HookPack（同一 Python 进程 / 同一 venv）契合。
- **Agent 开发时用官方 CLI Skills，不要当成插件运行时依赖**：仓库 [larksuite/cli](https://github.com/larksuite/cli)。与四项直接对应的是 `lark-drive`、`lark-base`、`lark-sheets`、`lark-im`；`lark-shared` 是认证前置。安装：`npx @larksuite/cli@latest install`。
- **官方 Node SDK 与官方 MCP 都不适合嵌进 HookPack**：Node SDK（`@larksuiteoapi/node-sdk`）能调服务端 API，但是 Node 库，根目录没有 `skills/`。MCP 是给 AI 调的服务，不是进程内库。开放平台概述写远程 MCP 当前只支持云文档，Base 等「后续发布」；GitHub 上的本地 MCP 工具更多，但概述把本地模式标成不推荐，且文件上传下载在仓库 README 里写明暂不支持。
- **社区技能不作为主依据**：`https://github.com/wenerme/ai/tree/main/skills/lark-node-sdk` 不在 `larksuite` 组织下，非官方，不推荐。
- **四项都有官方 OpenAPI**，插件最终调用的是这些接口，SDK / CLI / MCP 只是封装。

## 1. 四项能力 → 成熟工具对照

云空间能否当「项目持久化文件」：可以，对象是云空间文件夹里的文件，不是本机磁盘。官方上传接口把文件传到云空间指定文件夹（`parent_type` 固定 `explorer`）。不超过 20MB 用整文件上传；更大走分片。接口不支持把文件直接传到知识库。来源：[上传文件](https://open.feishu.cn/document/server-docs/docs/drive-v1/upload/upload_all.md)。`lark-drive` 的术语说明把云空间、云盘、云存储视为同一产品。来源：[lark-drive SKILL.md](https://raw.githubusercontent.com/larksuite/cli/main/skills/lark-drive/SKILL.md)。

## 2. 官方 skill：哪些能用

`skills/` 目录实际有 28 个 skill（[目录列表](https://github.com/larksuite/cli/tree/main/skills)）。[README.zh.md](https://raw.githubusercontent.com/larksuite/cli/main/README.zh.md) 开篇写「26 个」Skills，文中表格列出 23 个；以目录为准，表格未列出 `lark-apps`、`lark-minutes`、`lark-note`、`lark-vc`、`lark-vc-agent`。本次只读了与四项相关的 SKILL.md，这五个未展开。

CLI 是三层调用，都给人和 Agent 用，不是 Python 库：快捷命令（`+` 前缀）、已注册 API 命令、`lark-cli api` 裸调任意端点。来源同上 README。

### 可用（Agent 开发这四件事）

- **`lark-shared`**：所有 skill 的认证底座（登录、user/bot 身份、scope）。不直接完成四件事，但其它 skill 要求先读它。来源：[SKILL.md](https://raw.githubusercontent.com/larksuite/cli/main/skills/lark-shared/SKILL.md)。
- **`lark-drive`**：云空间文件上传、下载、文件夹、权限、导入导出。表内数据不归它。
- **`lark-base`**：多维表格的表、字段、记录、视图。本地 Excel/CSV 导入成 Base 要先走 `lark-drive` 的 `+import`。
- **`lark-sheets`**：电子表格读写、追加、查找、导出。
- **`lark-im`**：发消息、回复、群管理。发消息用 `+messages-send`。

### 与「保存文件」只沾边，不当主路径

- **`lark-doc`**：读写的是云文档 Docx 正文，不是任意文件落盘。文件级上传下载它明确推给 `lark-drive`。来源：[SKILL.md](https://raw.githubusercontent.com/larksuite/cli/main/skills/lark-doc/SKILL.md)。
- **`lark-markdown`**：只处理云空间里的原生 `.md` 文件（创建、读取、覆盖、本地替换后再上传）。普通二进制或非 md 持久化仍用 `lark-drive`。来源：[SKILL.md](https://raw.githubusercontent.com/larksuite/cli/main/skills/lark-markdown/SKILL.md)。

### 不直接完成这四件事

- **`lark-openapi-explorer`**：现有 skill 盖不住时，从 `https://open.feishu.cn/llms.txt` 挖原生 API，再用 `lark-cli api` 调用。来源：[SKILL.md](https://raw.githubusercontent.com/larksuite/cli/main/skills/lark-openapi-explorer/SKILL.md)。
- **`lark-skill-maker`**：把 API 编排写成新的 `SKILL.md`。来源：[SKILL.md](https://raw.githubusercontent.com/larksuite/cli/main/skills/lark-skill-maker/SKILL.md)。

### 本次四项用不上

日历、幻灯片、任务、邮箱、通讯录、知识库节点、事件订阅、会议、画板、考勤、审批、会议纪要/站会工作流、OKR（README 表中的 `lark-calendar`、`lark-slides`、`lark-task`、`lark-mail`、`lark-contact`、`lark-wiki`、`lark-event`、`lark-meeting`、`lark-whiteboard`、`lark-attendance`、`lark-approval`、`lark-workflow-meeting-summary`、`lark-workflow-standup-report`、`lark-okr`）。名称与四项无关，本次没有把它们的 SKILL.md 当能力依据。

## 3. 与本项目插件模型的契合

本仓库插件是导出 `PACK`（`HookPack`）的 Python 文件，引擎启动时加载，与引擎同一 Python 环境。来源：[plugin-development.md](../../../development/plugin-development.md)。仓库内检索 `feishu` / `lark` / `飞书` 无匹配，目前没有飞书代码。

因此：

- **运行时**：在 HookPack 所在进程里 `import lark_oapi`，用官方 Python SDK 调 Drive / Bitable / Sheets / IM。不要把 `lark-cli` 或 MCP 进程当作插件依赖。
- **开发时**：Agent 可以用 `lark-drive` / `lark-base` / `lark-sheets` / `lark-im`（先 `lark-shared`）查命令和权限；查漏用 `lark-openapi-explorer`。这些 skill 教的是终端命令，不会被引擎加载。
- **不要用 Node SDK 当插件库**：包是 `@larksuiteoapi/node-sdk`，README 的调用形态是 `new lark.Client(...)`。仓库根目录列表没有 `skills` 目录（有 `client`、`code-gen`、`docs` 等）。来源：[根目录](https://github.com/larksuite/node-sdk)、[README.zh.md](https://raw.githubusercontent.com/larksuite/node-sdk/main/README.zh.md)。
- **不要用 MCP 当插件库**。两份官方材料要分开读：
  - 开放平台概述：MCP 是把 OpenAPI 封装成给大模型用的工具。远程调用当前只支持云文档；Base、日历等写的是后续发布。本地调用写明支持全部服务端 OpenAPI，但标注不推荐，且要自己部署。来源：[MCP 概述](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/mcp_integration/mcp_introduction.md)。
  - GitHub 仓库 `larksuite/lark-openapi-mcp`（npm `@larksuiteoapi/lark-mcp`）自述为官方 OpenAPI MCP，给 Trae / Cursor 等客户端用，文首标 Beta，并写文件上传下载暂不支持。来源：[README_ZH.md](https://raw.githubusercontent.com/larksuite/lark-openapi-mcp/main/README_ZH.md)。

Python SDK 用法（只记入口，不是本仓库实现）：

```bash
pip install lark-oapi
```

```python
client = lark.Client.builder().app_id("cli_xxx").app_secret("...").build()
response = client.im.v1.message.create(request)
```

来源：[oapi-sdk-python README](https://raw.githubusercontent.com/larksuite/oapi-sdk-python/v2_main/README.md)。开放平台索引也把 `oapi-sdk-python` 列为服务端 SDK。来源：[llms.txt](https://open.feishu.cn/llms.txt)。

## 4. 四项官方 OpenAPI（各一条）

文档 URL 加 `.md` 可取 Markdown，这一点由 `lark-openapi-explorer` 写明，本次四条 `.md` 均打开成功。

| 能力 | 文档 | 方法与路径 |
|------|------|------------|
| 上传文件到云空间 | [上传文件](https://open.feishu.cn/document/server-docs/docs/drive-v1/upload/upload_all.md) | `POST /open-apis/drive/v1/files/upload_all`。`parent_type=explorer`，`parent_node` 为文件夹 token。大于 20MB 不要用此接口 |
| 多维表格新增记录 | [新增记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/create.md) | `POST /open-apis/bitable/v1/apps/:app_token/tables/:table_id/records`。权限其一：`base:record:create` 或 `bitable:app` |
| 电子表格写入 | [向单个范围写入数据](https://open.feishu.cn/document/server-docs/docs/sheets-v3/data-operation/write-data-to-a-single-range.md) | `PUT /open-apis/sheets/v2/spreadsheets/:spreadsheetToken/values`。范围内已有数据会被覆盖。单次最多 5000 行、100 列 |
| 发送消息 | [发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create.md) | `POST /open-apis/im/v1/messages`。查询参数 `receive_id_type`；应用身份发消息需机器人能力及 `im:message` / `im:message:send_as_bot` / `im:message:send` 之一 |

索引入口（已打开，正文为能力总览，具体 API 链接在模块文档里）：[https://open.feishu.cn/llms.txt](https://open.feishu.cn/llms.txt)。
